# Работа над Herbis

## Локальный запуск

Используйте Node.js 24 LTS (не ниже 24.14). Скопируйте `.env.example` в `.env` и выполните `npm start`. Внешних npm-зависимостей нет. Для проверки входа локально задайте `MAIL_DRIVER=file`: тестовые письма сохраняются рядом с базой, инструкция находится в `docs/EMAIL-LOGIN.md`.

## Изменения

Создавайте отдельную ветку для задачи, например `git switch -c feature/profile-layout`. Перед коммитом просматривайте `git diff` и запускайте `npm test`. В pull request опишите изменение поведения, проверку и известные ограничения. Для интерфейса добавьте скриншоты широкого и мобильного экранов.

Главная и вход находятся в `public/assets/views.js`, кабинет — в `cabinet.js`. Базовая вёрстка — в `styles.css`, общая тема — в `theme.css`, оформление кабинета — в `cabinet.css`. Обработчики событий и маршруты находятся в `app.js`.

## Данные и интеграции

- Не коммитьте `.env`, базы, почтовый outbox, резервные копии, реальные коды и учётные данные. Примеры конфигурации держите в `.env.example` с пустыми или явно условными значениями.
- Авторизация, цены, принадлежность данных и ограничения доступа проверяются сервером. Проверки только в браузере не заменяют серверные.
- Изменения SQLite оформляйте миграциями в `server/database.mjs`, сохраняя существующие данные. Не переименовывайте внутренние ID тарифов или cookie без плана совместимости.
- Не включайте фиктивный успешный ответ оплаты, VPN или OAuth. Подключение провайдеров описано в `docs/INTEGRATIONS.md`.
- Тесты используют временные базы и файловую почту. Рабочую базу сервиса для тестов не используйте.

GitHub Actions настроен на проверки в Windows и Linux. Фактический результат этих запусков появится после отправки репозитория на GitHub; локальная проверка выполнена на Windows.
